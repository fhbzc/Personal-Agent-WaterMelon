Stages

Not this work

State heartbeat states grouped by what they are about, and a summary per group. Every button below is marked (real data) or (sandbox) - the two are the same code over different folders, and only the first kind changes anything of yours. The page follows a round while it runs and stops when it stops, so there is nothing to refresh.
Run one now (real data)
One real round, immediately, instead of waiting for the hour. It reads your states, appends the new ones to the tasks already there, and rebuilds only if a signal says appending has stopped being honest. It writes real records - tasks in the library, rows in the database - and costs a model call for each task whose summary has gone out of date. What it writes is the tasks themselves. The working-out - the instruction, each reply unaltered, whether it chose to search and what came back - is shown here while the round is on the page and is not written anywhere: copy what you want to keep.
Sandbox the same code, a different pair of folders - so the grouping can be judged against the shape that went in. It READS your states, to copy them in; it writes nothing of yours - not your states, not your library, not your tasks.
states / over days (sandbox)
How many states to put in, and how far back to spread them. Real ones are copied first; any shortfall is invented, and the invented ones are worded several ways within each subject on purpose, because a sandbox whose states repeat one sentence tests nothing - matching identical text is not what the grouping does.
Make some up (sandbox)
Fills the sandbox's own states/ folder: copies of your real states first, and invented ones only to make up a shortfall. The copies are what make a run worth reading - invented states are five sentences per subject, and separating five sentences is an easier question than the real one. A copy takes the words and the span and nothing else. Nothing of yours is written to - not your states, not your library, not your tasks.
Run one now (in sandbox)
Empties the sandbox, fills it, and runs one round - a whole demonstration in one press. It was half of one: it ran over whatever happened to be in the sandbox, so on a sandbox nobody had filled it read nothing and drew nothing, which reads as a fault in the grouping rather than as an empty folder. The same code as Run one now (real data), handed a different pair of folders and a different set of task rows. Summaries are written here, as they now are for the real round, because a summary is what you came to look at - so this does cost model calls. They were off for the real round while the grouping itself was what was being worked on, which is no longer true. Two presses will not show appending, and cannot: each is a fresh grouping of fresh states. Rehearse appending is what shows that.
Rehearse appending (sandbox)
The whole mechanism in one press, and the only way to see all of it. It empties the sandbox, writes more states than the window holds so the cap is doing something, runs a round, adds more and runs again, then adds more and runs a third time. The second and third rounds are both appending rounds - a few dot products against the task centres and no tree at all. There were three because the second one used to rebuild every time, which was a defect and is fixed; the third stays because a second consecutive append is worth seeing, and because it is where a pile of leftovers becomes a task of its own without a rebuild. Each round gets its own overview, and the totals on them are the folder's own count.
Empty it (sandbox)
Deletes everything in the sandbox and says what was in it. Two kinds of thing, counted apart because they do not match one to one: files are what you can open - the made-up states, and the write-up of each task found from them - and rows are the bookkeeping behind them: which tasks there are, what each round did, and which states fitted nowhere. One task is one row and one write-up over many state files. Only the sandbox: it cannot reach the real ones, and there is a test that says so.

Nothing to show. The grouping itself needs no model - each state is read as a vector, the closest are joined into a tree, and the tree is read as two layers of tasks - but a model call is made for each task that needs a summary, and only where enough of what a task holds has turned over to make the summary it already has wrong. The page follows a round while it runs.

Models

The models the agent thinks with, in order. Each call goes to the first one that works. When one cannot answer - its sign-in has expired, its key is refused, its credit or usage limit is used up, it is not installed - the next one answers, and the first is used again once it works. A call that only timed out is tried again, not passed on.

    Heartbeats

    How often each runs, in minutes. The agent heartbeat reads what you have been doing and writes it down; the state heartbeat groups that into your tasks and projects.

    Web search

    What it is for. When an agent needs something from the public web, it searches and reads public pages:

    • a work run looking up documentation, data or facts for the work;
    • Connections, looking for your contacts' public news and your own public profile;
    • the web part of What you need to know.

    How the model goes about it. The model decides what to search, opens the pages worth reading, searches again from what it finds, and stops when it has what it needs. Only public pages: it never signs in to anything, and never posts or sends anything. A Connections round runs with every state heartbeat, so it has a guard set far past what a round needs: 200 model calls or 100 lookups.

    Which search. A model that has search of its own (Claude Code, Codex) always uses its own, and those searches count toward your plan with it; it is never given the app's beside it. A model without one, such as an API like DeepSeek, uses the app's search: the model asks and the app searches DuckDuckGo for it, which may now and then refuse an application. There is nothing to set.

    What may be searched and opened. Whichever search is used, a search may not carry anything that looks like a key or a password, and a page is opened only when nothing of yours can travel in its address: an address found in a search, on a page read, or in your instruction, files or records; any page of a site you named, or of a documentation, package, code or reference site; a known address made shorter; or, on any other site, a short address with no query, nothing like a key, and none of your own words in it - a few on each new site, and a few new sites in all, so nothing can be spelled out an address at a time. A site made to collect what is sent to it is opened only at an address that already exists there. Claude Code's own search is held to this by a check before and after each search and page. Codex's own search reads only the copy of the web OpenAI keeps; the sites it finds count as found, and live pages it reads with the app's tools.

    macOS permissions

    macOS asks for each of these on its own, and only you can switch them on, in System Settings. Start with Full Disk Access: it also covers your Desktop, Documents and Downloads folders, so macOS will not ask about each of them. After an update, macOS may ask for them again.

    Privacy

    What the agent listens to, each its own switch - all on by default. Each one off, the agent knows less of what you do; each one on, the computer does more work. Changing these changes performance: reading the text on screen and taking pictures of windows cost the most.

    Shortcuts

    Keys that work in every program while the agent runs. To change one, click Change and press the keys you want.
